# Аудит «Явки» перед MVP 1.0

Дата: 11 октября 2026 года.

## Результат

Подключённый репозиторий `sardor2005/Yavka-2.0` не содержит исходников существующего приложения. Разработку MVP с сохранением интерфейса и прежних правил рейтинга нельзя начать до получения этих исходников. Новый React-проект, фиктивный backend и демонстрационные пользователи не создавались.

## Выполненные проверки

До добавления этой документации:

- Рабочая копия: `/workspace/Yavka-2.0`.
- `git status --short --branch`: `No commits yet on work`, изменений и пользовательских файлов нет.
- `git rev-parse --verify HEAD^{commit}`: отсутствует первый коммит.
- `git symbolic-ref HEAD`: `refs/heads/work`; соответствующего ref ещё нет. Это Git-репозиторий с веткой без первого коммита.
- `git ls-files --stage` и поиск файлов вне `.git`: исходные файлы отсутствуют.
- `git log --all --oneline` и `git show-ref`: локальных коммитов и refs нет.
- `git rev-parse --is-shallow-repository`: `false`; отсутствие истории не объясняется shallow clone.
- Origin указывает на `github.com/sardor2005/Yavka-2.0.git`.
- `git ls-remote --symref origin` завершился успешно, без refs. Доступ к GitHub работает; удалённые ветки и теги не обнаружены.
- `git ls-remote --exit-code origin refs/heads/main` завершился с кодом `2`: ветка `main` не найдена.
- Запрос к `https://yavka-rosy.vercel.app/` через существующий proxy вернул `CONNECT tunnel failed, response 403`. Домен отсутствует в действующем сетевом списке разрешений. HTML и assets не получены; это не доказательство неисправности сайта.

После проверки создана локальная ветка `feature/yavka-mvp-backend` для документов. Ветка `main` не создавалась и не изменялась.

## Необходимое действие владельца

В Vercel откройте существующий проект сайта, затем **Settings → Git** и найдите подключённый репозиторий. В настройках сборки проверьте корневой каталог проекта и production branch. Сообщите фактические репозиторий, ветку и каталог исходников либо перенесите существующие исходники в `sardor2005/Yavka-2.0` вместе с историей и lockfile. Не копируйте `.env`, секреты, `node_modules` и generated build вместо исходников.

Если проект существует только локально, опубликуйте именно его исходные файлы в нужном репозитории. Для полноценного PR понадобится существующая целевая ветка с исходным приложением. Не нужно создавать искусственную пустую `main` ради обхода блокера.

После получения кода необходимо повторить аудит и установить прежние правила начисления рейтинга до проектирования его серверной реализации.
