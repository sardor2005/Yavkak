## Изменения

Исходная beta хранила аккаунты и встречи в localStorage: второй пользователь не получал общую встречу, чат или фотографии. Теперь существующий React-интерфейс работает с Supabase Auth/PostgreSQL/Storage/Realtime. Сохранены логотип, русские тексты, фирменные стили и карточки; исходная beta архивирована в `legacy/beta/`.

Реализованы восемь модулей: подтверждаемый email/password Auth и профиль; встречи и история; приглашения друзьям и одноразовые ссылки с TTL/отзывом; отдельные RSVP и ручное прибытие с серверным временем; приватные сжатые фотографии; экспериментальный серверный рейтинг; поиск публичных профилей и друзья; приватный текстовый чат с историей и Realtime.

Три миграции создают десять прикладных сущностей, RLS, ограничения, индексы и доверенные RPC. Клиент не назначает баллы, автора или права доступа. Завершение идемпотентно, ошибочный результат можно отменить; отмена встречи обращает начисления. Новое правило рейтинга: +10 за ручное прибытие не позже начала, 0 за опоздание, −5 за отсутствие отметки среди принявших участие. GPS не используется.

Storage ограничен членством, авторством удаления, MIME, 2 МиБ на файл и шестью фото на встречу. Проверка окончательной metadata выполняется и для внутренней записи Storage. Для Realtime клиент повторно читает данные после фактической готовности PostgreSQL Changes; восстановление сети дополнено сверкой через API. Привилегированные ключи отклоняются до сборки frontend.

## Проверки

Проверено 11 октября 2026 года на настоящем локальном Supabase с разными Auth UUID и обычными пользовательскими сессиями:

- `npm ci` и `npm run build`: PASS.
- `npm test`: 23 passed; 17 относятся к сохранённому legacy-сервису, 6 — новые timezone/календарь/защита ключей.
- `npm run test:sql`: PASS; три миграции и 212 SQL-операторов, включая отрицательные RLS/RPC/Storage проверки.
- `npm run test:integration`: 11 passed, 0 failed, 0 skipped — десять сценариев и общий test group. Реальные Auth-письма Mailpit, recovery, три аккаунта, HTTP, Storage, доставка WebSocket, рейтинг и запреты для постороннего.
- `npm run test:e2e:live`: 4 passed, 0 failed, 0 skipped на desktop/mobile. Два аккаунта проходят друзей, приглашение, чат, статусы, фото и завершение; данные сохраняются после reload/relogin, сообщения догружаются после восстановления сети, фокус остаётся в модальном окне.

Полный охват и ограничения: [docs/TESTING.md](https://github.com/sardor2005/Yavka/blob/feature/yavka-mvp-backend/docs/TESTING.md).

## Перед публичным запуском

Облачный Supabase-проект ещё не создан. Cloud SMTP, публичный Vercel deployment и два физических устройства не проверены. Локальные тесты не заменяют эту проверку.

Владелец создаёт Supabase Free, применяет три миграции, проверяет Auth-письма/redirect URL и приватный bucket, добавляет URL и публичный publishable key в существующий Vercel Hobby и проверяет preview под тремя независимыми аккаунтами. Пошаговая инструкция: [docs/DEPLOYMENT.md](https://github.com/sardor2005/Yavka/blob/feature/yavka-mvp-backend/docs/DEPLOYMENT.md). Затем владелец решает вопрос merge/deployment и резервного копирования базы вместе с файлами Storage.

Триггер на управляемой `storage.objects` проверен с локальным Storage v1.35.3; после обновления провайдера необходима повторная проверка протокола загрузки и восстановления. Отзыв доступа запрещает будущие авторизованные чтения, но не удаляет уже скачанные файлы с чужого устройства.

GPS, ИИ-гид, достопримечательности, погода/ETA и push отложены: [docs/DEFERRED_FEATURES.md](https://github.com/sardor2005/Yavka/blob/feature/yavka-mvp-backend/docs/DEFERRED_FEATURES.md). Автоматический перенос старых localStorage-записей в реальные аккаунты не выполняется.
