## Изменения

В выбранном владельцем репозитории `Yavka2` (прежнее имя — `Yavka-2.0`) были только шесть подготовительных документов. Теперь в него перенесён готовый MVP из `sardor2005/Yavka` объединением историй Git. Оба исходных набора коммитов сохранены; прежние документы целевого репозитория архивированы в `legacy/repository-onboarding/`. Исходный репозиторий приложения сохранён. Инструкции обновлены для нового репозитория и Preview ветки переноса.

Исходная beta хранила аккаунты и встречи в localStorage: второй пользователь не получал общую встречу, чат или фотографии. Теперь существующий React-интерфейс работает с Supabase Auth/PostgreSQL/Storage/Realtime. Сохранены логотип, русские тексты, фирменные стили и карточки; исходная beta архивирована в `legacy/beta/`.

Реализованы восемь модулей: подтверждаемый email/password Auth и профиль; встречи и история; приглашения друзьям и одноразовые ссылки с TTL/отзывом; отдельные RSVP и ручное прибытие с серверным временем; приватные сжатые фотографии; экспериментальный серверный рейтинг; поиск публичных профилей и друзья; приватный текстовый чат с историей и Realtime.

Три миграции создают десять прикладных сущностей, RLS, ограничения, индексы и доверенные RPC. Клиент не назначает баллы, автора или права доступа. Завершение идемпотентно, ошибочный результат можно отменить; отмена встречи обращает начисления. Новое правило рейтинга: +10 за ручное прибытие не позже начала, 0 за опоздание, −5 за отсутствие отметки среди принявших участие. GPS не используется.

Storage ограничен членством, авторством удаления, MIME, 2 МиБ на файл и шестью фото на встречу. Проверка окончательной metadata выполняется и для внутренней записи Storage. Для Realtime клиент повторно читает данные после фактической готовности PostgreSQL Changes; восстановление сети дополнено сверкой через API. Привилегированные ключи отклоняются до сборки frontend.

## Проверки

Проверено 11 октября 2026 года в исходной рабочей копии `/workspace/Yavka` на настоящем локальном Supabase с разными Auth UUID и обычными пользовательскими сессиями:

- `npm ci` и `npm run build`: PASS.
- `npm test`: 23 passed; 17 относятся к сохранённому legacy-сервису, 6 — новые timezone/календарь/защита ключей.
- `npm run test:sql`: PASS; три миграции и 212 SQL-операторов, включая отрицательные RLS/RPC/Storage проверки.
- `npm run test:integration`: 11 passed, 0 failed, 0 skipped — десять сценариев и общий test group. Реальные Auth-письма Mailpit, recovery, три аккаунта, HTTP, Storage, доставка WebSocket, рейтинг и запреты для постороннего.
- `npm run test:e2e:live`: 4 passed, 0 failed, 0 skipped на desktop/mobile. Два аккаунта проходят друзей, приглашение, чат, статусы, фото и завершение; данные сохраняются после reload/relogin, сообщения догружаются после восстановления сети, фокус остаётся в модальном окне.

После переноса 12 октября (Asia/Tashkent) из `/workspace/Yavka-2.0` повторены `npm ci` и `npm run check`: установка, сборка, 23 локальные проверки, три миграции и 212 SQL-операторов прошли. Повторный `npm run test:integration` также прошёл: 11 passed, 0 failed, 0 skipped на настоящем локальном Auth/Mailpit/PostgREST/Storage/Realtime. На момент импорта приложение, тесты, миграции, lockfile и конфигурация сборки совпадали с исходным MVP `aec3805`; обе истории входят в новую ветку.

Первый live браузерный запуск после переноса дал 3 passed и 1 failed: при потере сети повторное чтение встречи очищало загруженную страницу, поэтому desktop-тест не получал ожидаемый alert чата. Исправление в двух файлах приложения сохраняет загруженную встречу при `NETWORK_ERROR` и показывает ошибку с повтором; отказ доступа по-прежнему очищает встречу. E2E теперь проверяет заголовок, старое сообщение, alert чата и восстановление сети. Итоговое дерево отличается от исходного MVP этим исправлением; миграции и SQL не менялись.

После исправления `npm run build` и `npm test` прошли (23 passed), а последний `npm run test:e2e:live` завершился успешно: **4 passed, 0 failed, 0 skipped**, 29,7 секунды на desktop и mobile.

Полный охват и ограничения: [docs/TESTING.md](https://github.com/sardor2005/Yavka2/blob/feature/yavka-mvp-import/docs/TESTING.md).

## Перед публичным запуском

Владелец создал облачный Supabase-проект и подтвердил успешное применение трёх миграций. Cloud API/SMTP, публичный Vercel deployment и два физических устройства пока не проверены. Локальные тесты не заменяют эту проверку.

Владелец проверяет Auth-письма/redirect URL и приватный bucket созданного проекта, подключает `sardor2005/Yavka2` в существующем Vercel Hobby, добавляет URL и публичный publishable key для **Preview** и развёртывает **`feature/yavka-mvp-import`**. GPS, ИИ-гид, достопримечательности, погода/ETA и push отложены: [docs/DEFERRED_FEATURES.md](https://github.com/sardor2005/Yavka2/blob/feature/yavka-mvp-import/docs/DEFERRED_FEATURES.md). Автоматический перенос старых localStorage-записей в реальные аккаунты не выполняется.
